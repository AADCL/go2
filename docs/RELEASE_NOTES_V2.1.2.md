# GO2 V2.1.2 发布说明

发布日期：2026-09-12。以 `v2.1.1` 为基线追加发布，源码与机器狗 1 已编译、已部署的修复逐文件核对一致。用户在发布前现场反馈“没问题了”。

本版修复遥控前进/转向后控制永久 Disable、目标丢失，以及再次 Enable 时经典步态请求被拒绝的问题。原 `run_go2 mapping`、`export-map`、`navigation` 和首次 `enable` 流程保留。

## 改动

- 正确区分 `SwitchJoystick(1027)` 与步态/姿态 API。普通遥控介入暂停自动速度输出，保留原目标及公开 Action；摇杆回中稳定 1 秒且健康检查通过后，从当前位置重规划并续走原目标。暂停中发布的新目标替换原目标。
- 遥控数据使用本机实际提供的 `rt/lowstate.wireless_remote`，按 Unitree 官方 40 字节布局校验、解码。现场 5 秒采样收到 2477 条 LowState，而两个独立遥控话题均无数据。
- 普通摇杆恢复沿用此前已确认的经典步态选择，复核控制器而不重复切换。显式 Enable 仍要求 `ClassicWalk(true)` 成功；仅首次 `-1` 时增加一次有界关闭/开启准备，各步都必须成功。通信和其他错误不被当作成功。
- 新增有序 `/go2/control/state` 和限定用途的 `resume_after_manual` 服务，保留原 Bool 状态接口兼容性。
- SDK 等待改为后台服务调用，取消和健康心跳继续处理；内部取消绑定确切目标 ID，旧结果通过 generation 丢弃，避免误取消恢复后的新执行。
- 显式取消、reset、Disable、姿态/步态接管或健康故障仍终止自动续走。准备过程中重新核对恢复资格，防止并发停止被覆盖。

## 验证

- 机器狗 1 上 `go2_control`、`go2_navigation` 编译成功。
- 16 个控制单元测试、13 个导航集成测试通过，无失败。包括旧目标保留、新目标替换、Action/RViz 取消、reset、定位/地形故障、SDK 拒绝、慢服务与取消交错、过期 Bool 消息。
- 导航集成测试使用独立 ROS master、模拟服务和内部 Action server；未启动真实 SDK 节点或发送真机运动指令。
- 发布前重新校验已部署源码、二进制和诊断文档；启动脚本、外参及导航配置校验值保持不变。
- 用户后续现场反馈当前版本正常。本次不宣称获得了固件无法提供的物理步态确认，也未新增量化爬坡性能结论。

## 升级与历史

关闭旧导航进程后重新编译并按原命令启动；首次完成定位后执行 `run_go2 enable`。后续普通遥控操作结束不需要再次 Enable，否则显式 Enable 的旧目标清理流程仍会生效。

建图、地图转换、地形阈值、TF、外参、速度、footprint、TEB 和网络配置不变。本次仅追加 `main` 提交及 `v2.1.2` 标签，保留所有旧标签、提交及机器狗 2/3 的 `unitree-orin-nano` 分支。构建产物、bag、运行日志和临时认证文件不纳入本次源码提交。

部署诊断与测试步骤见[遥控接管与目标恢复](DEPLOYMENT_MANUAL_RESUME_20260912.md)。该文档记录部署当时的测试状态；发布前最新现场反馈见本发布说明。回退可在独立目录检出 `v2.1.1` 并重新编译。
